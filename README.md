# 投资组合分析与调仓模拟

基于固定行情快照的单用户原型。前端为 React + Vite，后端为 Node.js + Express。估值、集中度及交易校验均由后端计算；调仓仅用于模拟，不会修改原始组合。

## 环境与安装

- Node.js 22.x，最低 22.12.0；推荐 22.18.0（本项目实际验证版本）
- npm 10.x（实际验证版本：10.9.3）
- Git

在新电脑的终端执行：

```bash
git clone https://github.com/rebeccacyx/Investment.git
cd Investment
npm ci
```

以下命令均在仓库根目录（包含 `package.json` 的目录）执行。初始化组合与价格快照已随仓库放在 `data/portfolio.json`，无需导入数据、配置数据库或创建环境变量。`data/plans.json` 在首次成功保存方案时自动创建。

## 本地启动

打开两个终端，均进入仓库根目录，并保持运行：

终端 1（后端）：

```bash
npm start
```

终端 2（前端）：

```bash
npm run dev
```

在运行服务的**同一台电脑**上用浏览器打开 <http://127.0.0.1:5173/>。前端默认使用 5173 端口，并将 `/api` 请求转发到默认 3000 端口的后端。若端口已被占用，先停止占用程序再重试。无需公网部署。

## 手工验收 AC-01～AC-05

1. **AC-01 初始组合：**打开页面，核对「原始组合」总资产 ¥100,000、现金 ¥20,000、A01 400 股；持仓风险提示显示 A01 占比 40% 和科技行业占比 60% 两项超限。
2. **AC-02 阈值边界：**选择 SELL、A01、数量 100，点击「添加交易」。原始组合概览保持不变；在「调仓前后对比」中核对模拟后现金 ¥30,000、A01 市值 ¥30,000、A01 占比 30%、科技行业占比 50%、总资产 ¥100,000；风险提示变为「当前无超限提醒」。
3. **AC-03 连续操作：**接着选择 BUY、A02、数量 100 并添加。对比表应显示模拟后现金 ¥25,000、A01 300 股、A02 500 股且市值 ¥25,000、科技行业占比 55%、总资产 ¥100,000；风险区只显示科技行业超限。原始组合概览仍为现金 ¥20,000、A01 400 股、A02 400 股。
4. **AC-04 无效操作：**点击「重置模拟」，分别尝试 BUY A01 × 201、SELL A01 × 401，以及数量 0、负数和小数。操作应被拒绝并显示明确错误；先前已确认的模拟结果不应因失败而改变。每组独立场景可先重置再尝试。
5. **AC-05 保存与重开：**重新完成 AC-03 的两笔操作，输入方案名称并点击「保存当前方案」。确认方案出现在列表后，刷新浏览器页面，从列表点击「打开」：交易和模拟结果应以只读方式恢复。再停止并重新执行终端 1 的 `npm start`，刷新页面并再次打开同一方案；模拟后现金仍为 ¥25,000、A02 仍为 500 股，原始组合仍为现金 ¥20,000、A01 和 A02 各 400 股。保存文件 `data/plans.json` 会保留在仓库目录中；重新打开时后端根据保存的操作重新计算。

## 自动化测试与构建

```bash
npm test
npm run build
```

`npm test` 运行后端业务/API 测试与前端交互测试；`npm run build` 将前端构建到 `dist/`。`node_modules/`、`dist/` 和运行时 `data/plans.json` 不提交到仓库。

## 常见问题

- 页面无法打开：确认终端 2 已显示 Vite 启动成功，且 5173 端口未被占用。
- 页面提示无法连接：确认终端 1 已显示 API 启动成功；可在同一电脑访问 <http://127.0.0.1:3000/api/portfolio> 检查后端。
